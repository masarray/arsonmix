No automatic patch, arm, volume boost, change to MAIN/OBS or extra audio device. If the route is missing or disarmed, show a concise unavailable hint. No fake successful state. ## Engine
NativeFxCueBus owns fixed 2 x 4096 float scratch and a lock-free coherent CONTROL request (one writer, bounded one-attempt AUDIO read). Publisher exposes a callback-local scope only on the accepted graph/device revision and exact callback-observed independent MONITOR pair, hardware output allowed, not muted or reconfiguring or graph transition. Matching processor instance/prepare epoch claims scratch once and uses existing Control processAudioWithCue, no repeated render. Cue is substituted only into post-render MONITOR pair, after graph MAIN and external sinks already rendered. Existing secondary output copies native MAIN only. +0 additional buffering samples. Cue signal headroom -12dB, bounded +/-0.5, 5ms start/mode and MIX-return fade. Return uses last bounded cue sample faded into live normal monitor, not delayed dry. Hard route revoke, missing processor/bypass, failed callback, stale revision, mute or lease expiration fail closed; hard cancellation may be audible on monitor (not MAIN). A control timer expires after 500ms wall time and the audio lease after 0.5s processed samples; revoke cannot heartbeat-rearm. Hard reset on graph publication or physical rebinding. Single selected instance, no TLS refcounts, allocation or locks in added PCM loop. Scope does not authorize external hardware wiring; user must route MONITOR to private headphones. Requires independently verified pair; single-output safe setup audition not implemented. Analysis and detection remain same V2-P0A, not adaptive multiband yet.
