# DS-04B — native audio-owner control contract
The isolated Control owns exactly one Core. No UI thread access to DSP internals, no new render graph, no JSON in callback. Existing FxSpsc.h reused unchanged; static assertion for lock-free uint32 atomics. One serialized control producer submits commands and drains both outbound queues; one audio owner processes blocks. All prepare/replacement operations require both owners quiescent. Host must mint nonzero unique instance/epoch identities (never reuse an epoch for the same instance), bind them to existing FX slot/ChannelId or EdgeId and invalidate disconnected/replaced endpoints. Prepare validates settings and rate before changing anything, clears pending commands/ACK/telemetry when quiescent; abandoned requests must be failed by host rather than awaited forever.
 
Command: identity + strictly increasing nonzero 64-bit sequence + complete Settings + transient Audition. Submit true means enqueued only, never applied. Queue full returns false; host retains/coalesces unsent latest edits, handles deadlines, retries only with correct sequencing. Wrong identity rejected without advancing sequence; invalid payload consumes its sequence but leaves applied settings unchanged; retry with a new sequence. One ACK per consumed command, including reject, with actual accepted settings and applied sequence. ACK means accepted at audio block boundary, not that smoothed PCM or all subsequent commands are audible yet. Backpressure stops consumption when outbound ACK queue full; audio continues. Up to 8 commands/block, command/ACK 32 each, telemetry 8. Supported process block 1..4096 frames, mono/stereo nonoverlapping valid buffers; invalid block no command consumption. Host must not stall ACK drains or submit concurrently from multiple threads.
 
Snapshot: instance/epoch, applied sequence, processed frame count, actual settings, requested active audition, actual scalar gain reduction (not exact attenuation at each frequency), lower-band weight and cumulative telemetry-drop count. ACK snapshot is pre-block; telemetry snapshot post-block. Approximately <=30Hz, at most one per block, no catch-up bursts; full telemetry queue drops snapshots rather than stalls. Host drains to newest snapshot; stale UI indicator and readback timeout policy must be implemented in native bridge. No wall-clock timestamps yet.
 
Audition: Normal is default; Detect taps .5*(actual lower+upper bandpass samples) from same Core, not isolated sibilance or exact mathematical classifier decision. Delta is sanitized dry minus actual wet; phase residual may be audible. 5ms linear mix transitions with normalized weights; 3 seconds of processed samples lease, renewable only by fresh valid command. Expiry restores Normal without changing appliedSequence; telemetry carries active audition; prepare clears it. Disabled effect cannot request audition; normal switch ramps out. Host must renew only while explicitly auditioning, stop on close/disconnect, and fence or replace epoch on graph lifecycle. Lease uses audio frames, not wall time, and queued valid commands can still renew when drained; host cancellation and stale command deadlines remain integration work. No session persistence of audition. Audition currently substitutes the processed output of this isolated instance; do NOT route to public/audience PCM until host defines operator-only monitor admission, or explicit approved audition policy. No independent render path. Fixed 128-frame stack scratch chunks, no added sample buffering. Normal path uses no scratch copies and compile-time tap off.
 
Not yet native graph/WebView wiring, session, Detect monitor bus, timeout/reconnect controller, or preset store. Full implementation must preserve approved /preview/ GUI and existing routing; no new audio callback. No public release until real corpus/listening, physical FAT and merge gates.
