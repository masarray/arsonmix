# P1H — Real 10-Channel VST3 Inserts in Native Routing LAB
**Date:** 2026-10-28. **Baseline:** verified `main@240b90162bd240a10c76401b3637e3bf55df493c` — latest approved master/channel GUI, FX reorder, DearVR Orbit, portable workspace, clean 10-channel native dry BUS/PRE/POST routing, and Windows/Chromium CI. P1H extends the P1G **existing live routing audio callback**, not an alternate mixer engine.

## Actual delivery

- `LiveChannelFxGraph` is a **prepared, per-snapshot DSP graph**, privately owning up to 10 native JUCE AudioProcessor/VST3 instances (one independent stereo-compatible effect per strip), with its existing `PreparedMixerBlock`. No processor is shared across strips, the original CH1 rack, or old/new published snapshots. Plugins are released and destroyed after the realtime reader lease completes, **on the control thread**. An old graph can stay leased while a fully independently prepared replacement graph publishes, with no concurrent use of the same vendor processor.
- The signal path **really invokes `AudioProcessor::processBlock`** in the channel FX seam of P1D: physical MONO/STEREO source → independent VST3 → PRE send → fader/pan/mute/solo → POST send → BUS return with optional independent VST3 → MAIN. PRE effects and sends remain audible with source fader zero. Real peak metering from the DSP and existing 256-sample route fade remain intact.
- The verified plugin catalog, not WebView-provided file paths, resolves all per-strip FX choices. Identity `catalogId / physical file / uniqueId` is checked, instruments rejected, plugin bus negotiation reuses `src/VstBusLayout.h` with main stereo IN/OUT and optional sidechains disabled, instance creation + `prepareToPlay` happen off the realtime callback. Plugin creation failure, missing module, unsupported bus, invalid topology, stale epoch/revision, and malformed routes reject before graph publication. The previously published route continues untouched.
- **Zero-latency-only qualification:** until true PDC exists, reject plugins reporting nonzero `getLatencySamples()`, rather than mixing phase-misaligned direct and AUX paths. A mono-source strip can run a stereo-compatible plugin on dual-mono input, but true mono-only VST3 bus negotiation and mono-in/stereo-out special cases are not yet supported. Channel plugin maximum quantum comes from the device buffer size and callback is chunked without allocating; the 10-lane bus capacity remains preallocated 8192 frames. Existing DIRECT device identity fence, sample-rate epoch, callback I/O channel-count latching and operator MUTE gate still apply.
- Existing SIGNAL CHECK → ROUTING LAB now has a native VST3 selection under every channel (from catalog), while its physical pin, BUS, MAIN, MUTE, SOLO and send controls remain. UI is a **draft**, only APPLY while output is muted may publish, and the native acknowledgement carries `fxCount` and `sendCount`. STOP still mutes the outputs and returns to the **unchanged CH1** host. No changes to premium CH/MASTER strips, shaders, glow, Orbit or rack layout.
- New Windows JUCE native test uses separate synthetic processors (a CH1 insert and BUS return insert, with real `AudioProcessor::processBlock` sample multiplication), confirms PRE path at zero fader, no heap allocations in callback, new revision's sound is different, old graph remains valid while leased, and deferred processor release. Existing P1A–G CTests + JS/UI smoke are preserved on the SAME lean Windows workflow.

## Safe operator test (actual hardware FAT, headphones and low volume)
1. In `PLUGINS`, import/scan **one VST3 effect** into the existing catalog; choose a low-latency *effect* with an enabled stereo main bus and zero reported processing latency.
2. Remove CH1's old VST inserts before LAB (the legacy production CH1 rack remains isolated) and select a verified single-clock DIRECT ASIO/WASAPI device. MUTE OUTPUT in SIGNAL CHECK; no automatic device reopen.
3. Open ROUTING LAB, assign physical Mono IN port to CH1; choose the actual catalog VST3 under CH1. Set CH2 BUS and choose a **separately instantiated** VST3 return under CH2. CH1 MAIN off, CH1 FADER 0, CH2 MAIN on, add CH1→CH2 PRE send at -12dB.
4. APPLY TO NATIVE AUDIO while muted, check ACK (2 independent VST3 inserts, 1 send). Unmute at low headphone level, verify audio actually passes through both effects (not dry bypass), observe per-strip peak. Change CH1→CH2 to POST; mute and APPLY again; at zero source fader POST is silent.
5. STOP LAB; leave output muted and restore the previous production CH1 path. If the selected hardware disappears, a callback channel mask changes, or device epoch increments, output must remain silent until explicit reassignment. Try malformed source/send/plugin: previous graph must not be replaced.

## Non-completion / next gates
This is an **opt-in hardware LAB**, not the complete production 10-channel DAW/standalone console. Each strip currently accepts **one** VST3 stereo-compatible insert; multiple inserts/rack editor, mastering inserts, full mono bus layouts, true AUX hardware outputs, state backup/restore of LAB inserts, performance PDC, vendor exception containment, device-specific round-trip latency and issue #15 zero-VST crackle remain open. MIDI-generating plugins or processors that allocate internally are outside guaranteed RT allocation control. Vendor performance and sound quality are unproven until qualified on a real interface with VST3s. Native CTests cannot prove third-party plugin stability or hardware crackle absence.

Only merge after the **exact-head Windows x64 native application / CTest / signed zip verification** and Chromium UI smoke succeed and the latest main SHA is reconciled. Avoid blind merges of overlapping offline mixer PR #115/#117.
