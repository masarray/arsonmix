# ZBSH-09 — Runtime vendor fault evidence and safe recovery

Base 7160e6bdef67240001726fa1ba888787f665c6cd. Extends the pre-existing startup restore marker; ZBSH-06 discovery isolation is a separate pending change. No new audio FIFO, worker or plugin DSP bridge.

## Runtime lifetime journal
- One machine/process-owned control-thread journal in the selected Studio workspace, armed before cold description resolution and third-party construction. Covers direct ADD, dynamic ChannelId ADD, legacy preset restore, dry-routing/Show construction and session/unbound-editor factory. Persistent per-operation phase/module basename (not full paths or state) and a lifetime marker remain if the OS terminates the host. Controlled returns clear the operation marker, not the lifetime. Nested vendor construction is rejected rather than overwriting evidence.
- Lifetime marker is cleared only after ConsoleWindow destruction, including vendor owners and driver teardown, and only on resolved clean exit. Health probe cannot clear it. Existing startup marker and 15s window remain for legacy evidence.
- Prior interrupted lifetime or startup marker disables automatic session replay (including device reconnect), automatic MAIN resume, and automatic/shutdown session checkpoint writes. No deletion of .smix, plugin or preset. Existing verified PREVIOUS generation policy remains. Safe recovery is conservative: power loss, unrelated crashes, or forced termination can trigger it; it is not attribution to one vendor. A deliberate successful physical .smix Open acknowledges recovery; no inherited automatic MAIN arm in that transaction, then normal behavior may resume. If no valid safe file is available, export/edit a known-safe logical session explicitly and Open it with verified device. An unresolved safe-mode visit does not clear evidence.
- Existing direct and independent stream watchdogs remain; no new callback work, no automatic thread termination, process restart, ASIO buffer change or unsafe bypass. Actual in-process DSP/native editor access violation or hang can still kill or freeze mixer; marker helps next launch, cannot make current performance crash-proof. No per-module runtime denylist, no reliable blame for active graph crash; scanner quarantine comes from ZBSH-06. No hard power-loss durability guarantee or same-user malware protection.

## Recoverable C++ DSP exceptions
Existing catches muted only the failed block and retried the vendor on every subsequent callback. Now the exact dynamic/legacy processor owner is latched faulted; later PCM blocks do not reenter it, including bypass toggles and structural reuse. The failed path is silenced (not auto dry bypass). No new FIFO, per-block allocation, IO, locks or destruction. Existing atomic exception counter / a control-allocated shared atomic latch is used. Control timer reports one notice per fault episode, automatic MAIN/replay/checkpoint are blocked while the accepted fault is present. Faulted state capture refuses to overwrite valid snapshots. Remove/recreate or explicitly Open a verified session. Synthetic throwing JUCE processor CTest exercises one call, mute, no retry, bypass and state preservation. Not a handler for access violations, deadlocks or arbitrary native memory corruption.

## Qualification
New JUCE-core CTest starts its own executable as a child and exits without destructors after journal arm. Parent verifies persisted evidence, safe-mode retention, explicit acknowledgment, clean lifetime and path conflict, and preserved session bytes. Static checks cover construction count, safe recovery gates and shutdown ordering. Full Windows MSVC/CTest and real plugin/hardware FAT remain necessary. No installer release without integration with earlier security PRs.
