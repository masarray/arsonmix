# ZBSH-08 — Secure updater and persisted input

Independent source branch based on 7160e6bdef67240001726fa1ba888787f665c6cd; production automatic update requires ZBSH-05 trusted release publisher and actual attested Windows release. No release is created here.

## Upgrade, repair and rollback
Existing digest, byte-length, official download URL, provenance and approval checks remain. Every installer must also pass GitHub CLI attestation verification against masarray/arsonmix, the exact alpha publisher workflow, release branch, source/signer commit and hosted runner. Re-verify at execution while holding a read-only file share; recheck no active mixer. Verify rollback before committing an attempt and again before executing it. Only strictly newer upgrades, same-tag/same-SHA repair, and exact prior transaction rollback. Reject unexpected HTTPS redirects at every hop, bound metadata. A hash is not a signature. No silent downgrade to hash-only authentication.

Migration: the official GitHub CLI must be independently installed in Program Files/GitHub CLI/gh.exe and configured if required by the CLI; no automatic CLI download, PATH fallback, token acquisition or account requirement for mixer operation. If verifier/network/authentication/attestation is unavailable, defer auto-update and repair; no installer runs. Legacy releases have no retrospective attestation. Manually install the first independently verified attested release (after ZBSH-05 actually works); subsequent automatic update requires both current and candidate attested installers. This changes auto-update availability deliberately. Offline rollback now requires verification service access, not merely cached bytes; if unavailable, leave recovery to explicit manual installer. CLI and operating system trusted local installation are assumptions. This is not Authenticode or full TUF threshold/expiry/revocation protection. Same-user malware, compromised publisher account/workflow, and complete offline replay protection are out of scope. No user data is uploaded by this code; CLI contacts GitHub for verification and may use its existing credentials. No update during audio.

## Files
Shared bounded input helper checks actual reads and max nesting before recursive JSON parsing; typed schema/hash validation and transactional outputs remain. Applied to mixer document, .smix, mixer checkpoint blobs/pointers, built-in preset and native ZIP manifest; show codec receives structural guard and Show store bounds metadata and vendor blob reads. ZIP manifest decompresses with an actual byte ceiling, not declared size alone. Managed file paths reject JUCE-detected symbolic links; workspace relative references remain restricted and legacy absolute local paths remain supported. This does not sandbox hostile vendor VST state, prevent arbitrary same-user filesystem races, or certify every Windows reparse point. StudioBackup and remaining Show pointer/write IO audit, duplicate JSON key rejection and comprehensive fuzzing remain further work. No user preset format migration or deletion, no DSP callback changes.
