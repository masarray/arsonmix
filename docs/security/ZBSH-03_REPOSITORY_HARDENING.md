## Owner-only activation (not yet applied)

1. [Account password and authentication](https://github.com/settings/security): enable 2FA, add a passkey if available, save recovery codes offline before changing access. [Applications](https://github.com/settings/applications) and [tokens](https://github.com/settings/tokens): review unused access, expire/revoke only after confirming no live deployment depends on it. Never share passwords, tokens or recovery codes in chat or public issues. Maintain a verified recovery route.
2. [Rulesets](https://github.com/masarray/arsonmix/settings/rules): keep existing main ruleset unchanged. Use New ruleset / import a ruleset (if available), with [release-tags.json](rulesets/release-tags.json) and [release-branches.json](rulesets/release-branches.json). Review the displayed rule target and no-bypass config before activation. Tag pattern v* forbids updates/deletion but permits creation by existing write-authorized actors; alpha release branch pattern releases/alpha/* forbids deletion/force-push but permits ordinary candidate advancement and initial creation. Do NOT restrict creation or ordinary candidate updates until the current publisher design is adapted. This is not exclusive release creation authority. Retest the next intentional release with the existing trusted dispatcher; never experiment on existing published tags.
3. [Security settings](https://github.com/masarray/arsonmix/settings/security_analysis): enable private vulnerability reporting, dependency graph, Dependabot alerts/security updates, secret scanning and push protection wherever available free of charge. Inspect Security tab privately; resolve genuine leaked credentials by revocation/rotation first, not merely deleting Git history. Do not publish alert details. CodeQL/targeted dependency updates belong to ZBSH-04/07; do not enable an overlapping costly build blindly.
4. [Actions settings](https://github.com/masarray/arsonmix/settings/actions): verify default workflow token read-only, do not enable untrusted fork write tokens or secrets; preserve explicit owner dispatcher and status-publisher job permissions. Review app access and write collaborators privately; do not remove owner or release automation while active. Workflow-by-workflow permission split/pins are ZBSH-04.
5. [General settings](https://github.com/masarray/arsonmix/settings): do NOT switch on immutable releases yet. Existing crossplatform publisher adds Linux/macOS assets to the same published Windows alpha release. Immutable release would block that path. ZBSH-05 must collect all intended assets in draft before publication, or explicitly adopt a single-platform release contract, then verify immutable setting and future release. Historical releases are not automatically sealed.
6. Backup source plus release assets and configuration records to an independent safe location, no plaintext secrets. Restore test is ZBSH-11. Keep evidence private; never upload credential inventory.

Official reference: [rulesets and import](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/managing-rulesets-for-a-repository), [available rules](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/available-rules-for-rulesets), [repository security settings](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/enabling-features-for-your-repository/managing-security-and-analysis-settings-for-your-repository), [private reporting](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository).

## Acceptance and rollback

- PR tests pass at exact head; existing required CI remains authoritative. Verify main push audit or manual run on main, noting PASS / FAIL / PENDING / UNKNOWN explicitly. Rule recipes are candidate imports, not applied controls. No live mutation or bypass test on production refs.
- Owner confirms each admin control with non-sensitive status and date; repeat public metadata audit after changes. If a release path is blocked, investigate rule insights, do not remove main protection; adjust only newly imported release rule with owner approval and recorded reason. For a source regression revert the scoped PR through normal protected flow.
- Completion = source controls + verified owner-admin settings. If settings unavailable, mark milestone partial. No installer/FAT needed; no latency impact. ZBSH-04 handles supply chain and scanning, ZBSH-05 authenticated immutable release.
