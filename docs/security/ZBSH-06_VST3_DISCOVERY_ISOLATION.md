# ZBSH-06 — Isolated VST3 discovery and scan quarantine

Scope: metadata discovery for Plugin Catalog, explicit import, FactoryFX cold discovery and description cache misses (normal load, dry routing and session restore). Existing native processor instantiation and DSP remain in-process, with no new FIFO, IPC or buffering on the audio callback. This is failure containment, NOT a sandbox against malicious native code running as the same user.

## Implementation
- Same signed/unsigned installed executable, special worker flag, before normal JUCE single-instance gate, splash, mixer, ASIO, persistence or updater. No extra executable/installer dependency. Only the helper executes findAllTypesForFile. Parent uses one bounded child per cold module, no shell, no output pipe capture; 30s timeout, cancellation poll, bounded kill wait. Child self-exit deadline protects against orphaned hangs. Third-party subprocesses or kernel/FS hangs are not guaranteed to terminate.
- Per-run random temp receipt, bounded XML and class count, exact path/nonce/format, no DTD, preserve JUCE class order and both UID fields. Recheck metadata fingerprint before returning. No in-process scanning fallback; cached descriptors remain metadata only. V2 cache invalidates old format; normal startup can require a one-time rescan. WaveShell UID/name ambiguity still fails closed.
- Per-machine persistent quarantine marker is armed before child launch, cleared only on valid success or clean cancellation/launch failure without previous quarantine. Unchanged failed module is skipped on normal scan/load/restore; explicit re-import (including in-place) retries, changed metadata allows rescan. No deletion of original module or session. Existing catalog scan message reports failures. No GUI redesign. Cached catalog rows can remain visible; blocked cold load will not execute scanner, and explicit import is recovery.
- Metadata fingerprint is not cryptographic authenticity or TOCTOU protection. Verified FactoryFX continues its existing hash checks. PluginVault existing copy/rollback rules remain. Native plugin installation and execution still require operator trust; never assume an untrusted plugin is safe because it scanned.
- Control path cold cache miss waits for child up to 30 seconds per module; existing callback path is not touched, but session restore/control UI may take time. Network filesystem enumeration/copy may independently block. No physical audio or vendor compatibility claim before exact-binary FAT.
- ZBSH-09 must address runtime process faults, explicit load crash containment and recovery policy; true out-of-process DSP needs a separate latency/compatibility design. Do not add DSP bridge buffering for primary ASIO in this milestone.

## Qualification

Source contract checks scan call ownership and early application lifecycle. Need exact-SHA Windows compile and CTest, then real plugin vendor and hardware FAT. No installer or release claim until verified.
