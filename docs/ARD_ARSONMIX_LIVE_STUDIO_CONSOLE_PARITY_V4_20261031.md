## 1. Single authority boundaries
**Audio** = native C++ / JUCE / VST3; **UI** = WebView2 presentation/control only. No WebAudio alternative mixer, preview fake FX, independent JS routing truth, duplicate VST host, duplicate graph renderer, or new heavy UI framework. Maintain one primary native audio mix producer/callback and one active prepared graph; optional independently clocked **secondary output** uses an existing buffered consumer/ASRC bridge, not a second DSP mix producer. A caller may execute old renderer OR new renderer for controlled cutover, **never sum or process both on same live block**.

Ownership:
- `LiveAudioEngine`: one actual JUCE device owner/primary callback, hardware epoch and output gating; existing input diagnostics, physical MAIN/MONITOR taps, optional secondary consumer.
- `DynamicChannelRoster`: session graph **control-thread** source of truth; stable 64-bit IDs and one topology revision. Never infer ChannelId from browser visual column or hardware pin.
- `DynamicPreparedMixerBlock`: compiled bounded PCM schedule and preallocated scratch, mono/stereo format conversion and signals. Extend incrementally rather than building another mixing engine.
- `DynamicNativeSessionPublisher` (#244): stage and retire immutable compiled graph with epoch/revision validation, one leased render pointer. Safely integrate into `LiveAudioEngine` after PCM and live VST state parity; do not introduce another callback or second processor owner.
- One `NativeFxInstanceRegistry` (target abstraction): ChannelId+InsertId keyed actual JUCE VST3 instances and editors with unique instance identity, plugin chunks/permissions, sidechain layout and reported latency. Explicitly retire CH1 legacy special-case without dropping vendor Orbit/editor/Show. **No plugin copy or destruction on the audio thread.**
- `LiveParameterPlane` (target, separate from topology): immutable-address/index admission on control, bounded RT-safe atomics and sample/block dezipper in callback; native ACK only after accepted update. Existing #223/#231 AUX controls should be migrated, not reimplemented.
- `SessionStore/Show` (target): versioned dynamic ChannelId snapshot, output I/O profiles, plugin catalog class ID/state; migrate old 10CH Show without dropping unknown/vendor extensions.
- GUI `app.js`/`mixer-io.js`/`monitor.js`/`bridge.js`: *one* normalized `AcceptedSessionSnapshot`, `PendingEdit` overlay, and `NativeAck` events; no 10CH global array as future authority.

## 2. Canonical domain model and constraints
- `ChannelId:uint64`, `InsertId:uint64`, `SendId:uint64`, `ControlGroupId:uint64`, `OutputId:uint64`; names/display indices are mutable presentation only. Session membership and order separate from hardware endpoints.
- `ChannelRole = Input | AuxInput | GroupBus | FxReturn | Main | SubOutput | ListenBus | CueBus`. `VCA` is a control-node and never PCM renderer; `LinkedGroup` binds allowed fader/mute/solo controls only.
- `ChannelDefinition`: processing format (MONO/STEREO now; optional multichannel later), trim/polarity, pan law and stereo balance/dual-pan mode, fader/mute/solo, insert ordered references, primaryOut (0 or 1) + zero/more SendRef of typed purpose (`AudioPre`,`AudioPost`,`Sidechain`,`Cue`), sends pre/post tap, gain/pan, channel meter ID, accepted source identity.
- `InputPortRef = {backendId, endpointStableKey, deviceEpoch, verifiedPinOrdinal, channelMaskSignature}`; software input/output `LogicalIOId` persists independent from device. Remapping requires explicit user review. Actual enabled JUCE callback ordinal and physical pin labels MUST be translated by verified registry—not conflated. Never guess unavailable hardware.
- `OutputPortRef` bound to actual backend/endpoint and verified physical channel pins, exclusive ownership and safety policy; operator can route MAIN/Monitor/Cue/Sub/secondary to legal outputs. Do not hardwire virtual cable, OBS or particular brand.
- `SessionRevision`, `DeviceEpoch`, `GraphRevision`, `FxLeaseGeneration`, `RequestId`, `AcceptedAt` determine native ACK fences. No optimistic LIVE from UI draft.
- Processing order per input: `physical capture -> Input Gain/Polarity/format -> input inserts (optional) -> channel TRIM/HPF -> CH inserts / serial+parallel routing -> PRE send tap -> fader/mute/solo/pan -> POST send tap -> primary OUT`. Precisely define and regression-test PRE/POST versus channel DSP and fader; current legacy parity is the baseline, no unnoticed reordering. Sends and buses form a DAG with deterministic topological scheduling. Each return may contain a full insert chain and distinct output. Master FX must process before master gain/mono policy according to locked render ordering; monitor Listen paths must not inadvertently feed MAIN.
- A graph can contain any number of channels **within resource preflight** (memory, scratch frames, FX instances, CPU/deadline, verified hardware pins), not a fixed CH10 product cap. Unpatched/hidden channels should avoid expensive scratch and plugin instances unless intentionally kept active for tails.

## 3. Two data planes, one deterministic transaction
### A. Realtime parameter plane (audio remains armed)
Allow admitted gain, pan, mute/solo, linked-group/VCA controls, POST send gain, AUX gain, eligible plugin parameters, cue level, metering resets. Control thread validates ChannelId/SendId, graph revision, finite bounds, device epoch, accepted edge and plugin generation. Publish coalesced latest target via bounded lock-free/atomic transport. Callback reads once at bounded cadence, applies sample-accurate or <=64-sample dezipper as appropriate; no allocation, mutex, timer, JS or VST prepare. One in-flight ACK and latest desired target per control; no repeating MUTE/APPLY on every fader drag.

### B. Structural plane (off-RT compile + safe commit)
Add/remove/duplicate/reorder Channel, add/remove Group/FX, edit primaryOut/sends, mono/stereo format, plugin insert/reorder, pan topology, software I/O, Scenes, output destinations:
1. From accepted revision R and device epoch E, prepare candidate on control thread. Validate selected stable IDs, source pin masks, plugin availability, channel formats, bus layouts, typed sends, solo/monitor routing, caps and memory/CPU admission.
2. Kahn/DAG compile O(V+E); block cycles/feedback, duplicate edge, accidental double direct-to-MAIN, illegal output reachability or unsupported sidechain. Build scratch and plugin instances off RT, prewarm, load immutable verified state, calculate plugin latencies and PDC before publish.
3. **At present** keep existing MUTE/DISARM→APPLY→ACK for unsafe mutations, especially device/output switch. **Product target:** permit supported graph edits while sound continues via a proved safe, bounded old→new handoff (RT graph pointer swap with ramps/tails and sufficient resource headroom); if such preconditions fail, show "SAFE APPLY REQUIRES OUTPUT MUTE" and never auto-unmute. Do not trivially flip pointer from old engine while it owns vendor state.
4. Commit once with expected revision/device epoch/FX generation, graph lease. Renderer on block boundary reads exactly one accepted schedule. Retire old graph only after reader/Editor/Show references quiesce (bounded retirement pool; failure leaves accepted graph).
5. Return native `accepted|rejected|requiresDisarm` ACK including requestId, actual graph revision, device epoch, exact changed ChannelIds/levels. Reject stale pending operations and revert visual overlay. Never hide failure or "accept" on timer.

Explicit negative gates: armed output unsafe topology, output port changed, endpoint disappeared, plugin instance unsupported, sidechain mismatch, graph cycle, insufficient scratch/headroom, stale request, Show backup busy. Output armed controls always have deliberate panic mute and fail-silent on disconnection.

## 4. PDC and low-latency monitoring
- Plugin instance reports actual `getLatencySamples()` and bus format. Compute longest path latency per DAG node including serial inserts, parallel Splitter branches, buses/FX returns and sidechain alignment. Apply bounded preallocated sample delay to shorter paths before summing to avoid phase/flam/combing. Recompute on plugin topology/latency update *off RT*, guard memory; dynamic PDC state change is a structural transaction.
- Separate **Monitoring Low-Latency Policy** from normal compensated routing. User chooses `LOW LATENCY LIVE` vs `MAXIMUM FX COMPATIBILITY`; show plugin induced path latency and required bypass/disabled reason when a plugin cannot meet user's configured monitoring budget. Never silently double-monitor direct interface and native path. No implied exact imitation of Fender dropout-protection private internals.
- Display device-reported input/output buffer sample count and driver latency, measured round-trip only after loopback FAT, plugin PDC and secondary clock-bridge buffers distinctly. Audio callback period = `frames/sampleRate`. Set a measurable CPU/deadline target from real hardware rather than claiming universal 0 ms. Add callback gap/xrun, capture discontinuity, render underflow, drift and device-recovery counters with clear provenance.

## 5. VST3 and external processing
- Single class-ID validated plugin scan/catalog. Distinguish installed VST vs sample/mock. Per-channel instances are independent for duplicate/copy; preserve parameter values, serial state chunks, program and bypass. UI editor ownership keyed to unique InsertId/FX generation; never detach audio callback for simple GUI opening/drag/reorder.
- Typed stereo/mono VST3 main input/output, optional sidechain bus, plugin bus negotiation, channel splitter paths, host-event/tail state. Bypass and reorder either realtime envelope or prepared transaction, with de-click and no direct reuse of stale VST pointer.
- FactoryFX requires legal provenance, digest/UID/CID locks and tested actual bundled release; `config/factoryfx-approved-releases.json` empty is not "available". Original optional bus-level "console processing" can be built, but proprietary Studio Pro Mix Engine FX ABI is NOT compatible with VST3 by assumption.
- External hardware inserts require dedicated verified output+return pins, isolation from feedback, measured round-trip latency/PDC, device permission and operator explicit enable; P2 until safe physical FAT.

## 6. Console GUI integration contract
- One `AcceptedSessionSnapshot` native feed carries channels (stable IDs, roles, accepted IN/OUT/sends, fan-in, insert identity), devices/port names, bus graph revision, stage/mute/ARM status, FX latency and meters. UI may cache derived layout only. `PendingEdit` visually overlays without changing LIVE text/LED and is reset on rejection, epoch switch or Show recall.
- `web/app.js` current `const channels=raw.map(...)` and `renderMixer()` whole-strip rebuild are legacy bootstrap/demo. Replace incrementally with keyed `ChannelStripView[ChannelId]` and structural keyed diff. Do not treat mock scenes/FX names/simulated LUFS as native. Keep exactly one render owner for each panel; do not duplicate `monitor.js` route authority in `mixer-io.js`.
- `web/bridge.js` currently disables native Master FX/pan and owns CH1 legacy routing adapter; remove those restrictions **only after native parity** and verified ACK, not by changing disabled HTML.
- Fine-grained meters on stable DOM or low-cost canvas; cap UI rendering by display needs and throttle telemetry (target 30 Hz while active on standard GPU, tune by benchmark). Pointermove writes local cached UI control only, bounded emit; never `innerHTML` entire mixer, style blur/filter, text layout thrashing or VST redraw per mouse event.
- Semantic density: compact strips, pinned MAIN at right, context-sensitive editor (overlay/dock does not push graph), role banking, Input/Output panel, accepted connectivity badges, keyboard, focus, contrast; see GUI v4.

## 7. Scene, preset, control surface, recovery
- Create V5+ dynamic Show schema keyed ChannelId, displayOrder and type; migrate existing fixed `NativeShowSchema.h` V2/V4, preserve unknown future extension blocks and historic plugin checksums. Atomic write temp→fsync/rename with rollback. Scene diff+scope + Recall Safe (per channel and category); I/O mapping persists as logical channels and never silently ARM output. Native plugin instance restoration must be prevalidated before scene publish. Restore to last known good if vendor plugin load fails.
- MIDI/OSC/controller mapping is **optional mixer control** (not DAW note sequencing). Bind stable IDs to fader/VCA/pan/send/panic, consume on control plane; rate limit, protect panic route and audit remote source.
- Device recover: invalidation of epoch, purge stale ACK, maintain safe output MUTE, refresh verified inventory only from control thread, no auto reconnect to different pin/speaker, then deliberate operator rearm.

## 8. Implementation roadmap and code ownership
**M0/P0 physical**: #243 first sound and #241 raw PCM exist; prove real no-FX signal/route/output, isolate #15 WASAPI/clock/xrun, baseline 44.1/48k sample/buffer cases. No release until physical evidence.
**M1 native cutover**: `LiveAudioEngine.h`, `LiveDryRoutingLab.h` **and** `DynamicNativeSessionPublisher.h` one graph replacement; parity tests including CH1 Orbit/lease, 10CH+4 AUX, MAIN/MONITOR/secondary, full FxShow/Load, independent 12CH+Group+FX real PCM.
**M2 full ChannelId VST/route ownership**: retire CH1 special-case, per-ChannelId VST inserts/editors; live native additive channels/buses/FX; polygraph and send controls; only then show buttons.
**M3 Console**: replace fixed `web/app.js` mirror with native stable-ID dynamic projection, context actions, group selected, Click IN/OUT/SEND, strips and buses; one layout source.
**M4 PDC+Listen+Scenes**: native Master FX/pan, Cue/PFL/Listen, universal sidechain, scope-safe portable recall; no invalid phase summing.
**M5 advanced**: VCA/link groups, macro, parallel Splitter, external insert, optional multichannel/remote and measured low-end UI and hardware SOAK.

## 9. Proof matrix / blockers
C++ offline tests: legacy same-sample PCM A/B, 16-lane publisher regression, no feedback, valid AUX PRE/POST, phase and PDC impulse, solo/Listen isolation, zero-allocated RT, FX death/retirement, atomic scene rollback; JS contract + Chromium operator smoke; exact HEAD Windows MSVC/CTest/portable ZIP and WebView standalone parity. **Hardware FAT** requires ASIO and WASAPI mic/virtual playback, patched and muted capture PCM proof, armed real MAIN, PFL no MAIN leak, 0-FX crackle #15, multiple vendor VST3 editor opens/FX reorder, input/output device changes, independent-clock secondary, buffer/48k/44.1k and low-spec iGPU pointer load.
