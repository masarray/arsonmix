# AN-03D — source-aware Auto policy
Parent eb149ec8136023b42deb86ad7078dc96a889b2f1: focused CI 45554272183 and quick native CI 45554272166 PASS. Main 2253001926e6ef318eb00c9673417dc1177df4d6.
## Decision
User requires meaningful active noise reduction after Learn, not an idle-only gate. Resolve Auto from explicitly provided host source intent at prepare: SpeechMic -> Voice, SingingMic -> Singing, Music -> Music, Mixed/Unknown -> existing conservative AutoProtect. Explicit user modes override source intent. Do not infer a role from channel count, device name, microphone presence or spectral proxy. Source role is not a trained classifier and host wiring is not implemented. Unclassified foreground still receives unity: unresolved product blocker for general Auto. Do not market as automatic speech/music recognition. Resolve once at prepare/settings update, no new per-sample work, FFT, delay, allocation or dependency. Effective mode is cached in core; snapshot/ACK now reports requested settings, sourceRole and effectiveMode. Control rejects Learn in effective Music. Existing direct core Learn API and offline tests retain their earlier behavior; host control is authoritative. On graph epoch/source change, host must prepare new instance or quiescent drained control; profile invalidated on prepare, including same-role physical identity changes. Never silently carry a PSD between unrelated sources. Preserve existing manual override. No other FX, shared mixer, root CMake or GUI modified.
