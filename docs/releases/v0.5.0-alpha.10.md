# ArSonMix v0.5.0-alpha.10

Windows x64 **alpha preview** built from the current merged `main` development baseline. This is a field-test release, **not** a certified production or hardware-audio release.

## What changed since the alpha.9 release line

- **Merged native logical mixer milestone:** PR [#513](https://github.com/masarray/arsonmix/pull/513) is now integrated into `main`. A device-independent native `ChannelId`/`EdgeId` workspace supports add/delete/rename channels, buses, fader, pan, mute/solo, processing format, WIRE routing, parallel sends and SOURCE ONLY without making up hardware ports or simulated PCM.
- **Authoritative offline edits and `.smix`:** control-thread transaction and revision checks protect session create/edit/restore; disk commits, ACK and later native readback are distinct. Unsupported physical outputs, forged pins and stale edits are rejected rather than displayed as live audio.
- **Mixer GUI integration:** offline edit intents for tracks, buses, WIRE and FX rack planning are integrated with the approved native/Pages bridge. The released UI remains the single approved `/preview/` visual design; the browser preview itself cannot process hardware audio.
- **Native recovery and FX state:** the merged mixer retains already integrated verified ASIO-bound recovery, session-safe rack restoration, and the Harmonice and ArSon Player functionality described in alpha.9. These are subject to the limitations below.
- **Public delivery alignment:** the repository README, official landing page and download selection now identify actual uploaded assets per OS and prefer the direct Windows Setup EXE. Linux/macOS binaries must be qualified and uploaded separately; newer Windows features are not implied for older OS packages.

## Evidence and limitations

- The Windows release workflow must independently compile the exact candidate SHA with pinned JUCE and WebView2, run native CTest and GUI/package contracts, verify the portable package, build and test the Inno installer, and attach SHA256/provenance **before** publishing.
- **Physical ASIO/ASIO4ALL acceptance is still pending.** Automated tests are not evidence of uninterrupted live singing, no crackles, vendor VST3 state on real hardware, or every device-reconnect case.
- An offline-created logical session is not proof that arbitrary new physical IN/OUT bindings will immediately produce live PCM. Device graph binding, channel-to-channel WIRE and SOURCE ONLY must still be exercised with physical hardware.
- Harmonice's released DSP latency remains **32 ms**. The experimental 24/16 ms research and unmerged Vocal Throw work are **not included**. Draft PRs (including #512 and #521) are not automatically included just because they remain open.
- Treat this release as an **alpha preview for supervised, safe-volume testing**, not for unattended or mission-critical audio.
