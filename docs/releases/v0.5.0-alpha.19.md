# ArSonMix v0.5.0-alpha.19 — Windows Alpha Preview

## Startup window visibility fixed

**This alpha fixes the reported Windows startup problem where the loading splash disappears but the native mixer remains running behind other desktop windows.**

- Removed the forced `toBack()` call from the JUCE/WebView2 first-visible mixer frame. The opaque splash still covers early browser initialization.
- When the native GUI and audio startup handoff reports ready, ArSonMix restores and presents the mixer **once** with a best-effort transient Windows Z-order lift. The mixer immediately returns to ordinary non-topmost status—no persistent always-on-top behavior, no recurring foreground steals.
- The silent Smart Auto Updater health probe remains invisible and does not activate ASIO audio.
- Approved WebView2 geometry, native audio startup order, mixer session persistence and realtime processing are unchanged.

## Upgrade and Windows verification

Download the Windows x64 Setup ZIP from the [official release page](https://github.com/masarray/arsonmix/releases/tag/v0.5.0-alpha.19). Install over your previous ArSonMix alpha; Studio data, `.smix` sessions and user plugins are retained. Existing Inno-installed Alpha.18 may also offer this release through its Smart Auto Updater: accept the small update notice, close ArSonMix normally, then reopen it after installation.

After installation, open ArSonMix from the normal Start Menu/desktop launcher. Expected: splash appears, loading finishes, and the mixer stays **visible in front** and accepts input without Alt+Tab/taskbar recovery. The normal app window should still go behind other apps when you switch to them; it is not a pinned topmost window.

This remains a community open-source alpha without a paid code-signing requirement. Actual focus behavior depends on Windows foreground policy and must be confirmed on a real user desktop; CI proves native compile and startup contracts, not physical foreground visibility on every machine.
