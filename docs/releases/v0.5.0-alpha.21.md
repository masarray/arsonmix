# ArSonMix v0.5.0-alpha.21 — Guitar FX Picker visibility P0 correction

## The actual in-app fix

This release corrects an owner-confirmed regression reproduced using the exact prior Guitar FX FAT binary `v0.5.0-dev+g03ba6ecc`. That app displayed only four native built-in effects (Parametric EQ, Compressor, Harmonice, ArSon Vocal Throw) in the **BUILT-IN FX** section. The real **Guitar FX Rig** entry was incorrectly relegated to the lower **VST3 PLUGINS** section by `scripts/compose_native_peq.py` although its native JUCE DSP was present. It could be below the visible scroll region.

**Alpha.21 contains merged PR #657**, squash commit `54702c2796b6713dc6a936276b9c5c11b0f97135`. The compiled native FX Picker now places **Guitar FX Rig first inside BUILT-IN FX**, directly above the four existing special-effect controls. Guitar FX is automatically searchable by `guitar`; no VST3 scan, model download, or external plugin installation is needed. Registered native FX are not duplicated under VST3 plugins. This uses the real installed native processor ID `armix.builtin.guitar-rig.v1` and the existing generic native insert→ACK→editor mechanism; no demo/fake guitar processor was added.

**Older builds are not fixed**: the standalone g03ba6ecc FAT preview and already-published Alpha.19/Alpha.20 packages were compiled before this picker correction and should no longer be recommended for Guitar FX Picker testing.

## How to verify

1. Exit **every** running ArSonMix instance, including any separately extracted portable preview. Install **this Alpha.21** or extract its portable package into a *new* directory to avoid accidentally opening the g03ba6ecc executable again.
2. Open a channel FX Rack → **+ Add FX**. Verify the **first visible button in BUILT-IN FX is Guitar FX Rig** with `Native · Guitar`. It must not require scrolling down into VST3 PLUGINS. Search `guitar` and verify it remains visible.
3. Click Guitar FX Rig in an empty FX slot; only accept the effect as installed when the real native mixer ACK/readback verifies its `armix.builtin.guitar-rig.v1` instance. The JUCE native Guitar FX editor should open.
4. Only then connect a real guitar through a suitable Hi-Z/instrument interface input → ASIO → mixer channel → FX → WIRE → MAIN → physical playback (keep levels low). Audition Clean Studio / Warm Blues / Vintage Crunch / Modern Lead, knobs, bypass, CAB, A/B, saved `.smix`, and device rebind. Document actual ASIO hardware model, rate/buffer, glitches/xruns and physical latency; CI cannot prove audible output on a user's hardware.

## Evidence and qualification boundary

- Guitar FX core DSP + native registry were integrated in PR #607. The earlier source-matched Windows FAT at SHA `03ba6ecc` completed 92/92 CTests, **but did not have the corrected first-screen picker grouping**.
- The actual compiled picker repair in PR #657 was verified in Chromium cold-start and offline logical native GUI tests, including first-group position, uniqueness and selection behavior; fast source contracts passed.
- A broader unrelated visual test `tests/pages_inter_utility_v7_smoke.py` failed on a public preview MUTE/SOLO/PFL control assertion. This failure is disclosed, not called green. It does not read the modified Guitar FX files. No assertion of a fully green umbrella UI suite is made.
- The Alpha.21 release workflow must independently compile JUCE, verify the real embedded approved GUI resources, Windows GUI PE, checksums, and an Inno install/upgrade/uninstall candidate before publishing.
- This is a **Windows x64 alpha field-testing preview**, not a stable public audio quality release or proof of physical Hi-Z/ASIO qualification. Neural amplifier captures, commercial cabinet IRs and unimplemented guitar pedals are not represented as supported.
