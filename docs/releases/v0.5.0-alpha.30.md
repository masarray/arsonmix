# ArSonMix v0.5.0-alpha.30 — Accepted In-Mixer FX Workspace

This **public Windows x64 alpha preview** integrates the owner-tested FUX-1 editor workflow into protected `main`. It is a downloadable Windows installer and portable build, **not** a claim of production certification, measured ASIO round-trip latency or qualified dual-vendor ASIO.

## What's new

- **One mixer window for six built-in FX:** PEQ, Compressor, Graphic EQ 31, Harmonice, Vocal Throw and SonKu keep their original full-size hardware-face layouts inside the **existing approved `/preview/` native JUCE/WebView2 mixer**. No extra Windows popup is created for these six in-mixer editors.
- **Clipped, movable surfaces:** large editors remain at their intended size and clip naturally against the mixer viewport rather than being squeezed or reflowed. Drag the accessible header, use Alt+drag to reposition, Shift+wheel to pan horizontally, or double-click a header / the exact FX Rack slot to recenter. No second visual positioning owner overrides the native mixer editor transform.
- **Graphic EQ 31 remains fully operable:** all 31 fixed-frequency faders, separate Output trim, presets, real/native Power indication and S/M/L scale modes are retained. The shared FX Rack recenter path no longer overwrites the chosen GEQ31 scale.
- **Offline FX session protection:** retained/disconnected-session editor access is explicitly separated from live audio admission. Offline edits and persisted `.smix` intent require an explicit, authorized session reopen after matching hardware reconnect; they are not an excuse to silently arm output or fabricate a DSP ACK.
- **Preserved native authority:** one primary PCM/FX render graph, existing low-latency single-ASIO direct path, native ACK/readback, exact slot/ChannelId owner identity and vendor VST3 editor leases remain authoritative. Other experimental I/O and unaccepted Guitar FX workstreams are not silently enabled.

## Safe use and scope limitations

The tested functionality above is real, but do **not** imply independent two-vendor ASIO qualification, multiple audio render graphs, physical hot-unplug soak, calibrated live latency/CPU/XRUN measurements or vendor-wide VST3 compatibility. These remain separate hardware-dependent gates. The inactive historical secondary built-in FX window scaffold is **not** the user-facing editor path; its cleanup must be separately qualified and must not regress this accepted release.

Back up important `.smix` files before upgrading. Start monitoring muted or low, select an intentional single primary ASIO device, validate routing before raising the speaker level, and reopen the saved session explicitly after an offline device recovery. Optional factory VST3 are distributed only when independently approved by the packaging lock and provenance checks.
