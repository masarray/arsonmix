## Problem verified from code and field screenshot

P1I wires live strip faders only when the native routing session is ACTIVE. Signal Flow previously displayed a concept even in the Windows host.

## Implemented
- `LiveChannelFxGraph`: each immutable graph holds preprepared, shared **FxInstance** objects. Shared ownership copies **only on control thread**; audio callback dereferences a stable raw pointer, with zero heap/refcount/locks, and calls the actual JUCE AudioProcessor. Each instance owns its private MIDI scratch and vendor plugin, whose releaseResources runs on the control thread only after all old/new graph snapshots are safely retired. An atomic nonblocking try-enter guards vendor processing against unexpectedly overlapping callbacks: on contention, that strip is silenced instead of concurrently invoking the same VST3. C++ exceptions are caught inside the real callback and silently fail that strip (SEH/OS crashes remain outside this guarantee).
- `RealtimeRoutePublisher::controlPrepared` permits the single control thread to inspect the current graph only if the device epoch + expected revision match. Never call this from RT.
- On LAB APPLY, a matching **same-channel + identical catalog ID + same epoch + same device quantum** keeps the exact prior instance and vendor state. Changed/removed FX still instantiate/retire safely; old graph remains until all RT readers release. `fxReused` telemetry confirms the number carried forward and `fxCount` actual inserts. Rejected changes never replace previously published FX or routing.
- Native `acceptedRoute` is updated only after successful publication, included in status/ACK on the message thread. On Routing editor open, WebView hydrates physical ports/FX IDs/sends from this authoritative ACK, then overlays the current live fader/pan/mute/solo values from `channelControls`. Never replace the in-progress editor draft on periodic meter telemetry.
- `SIGNAL FLOW` tab in the Windows host now truthfully depicts the 10-channel native routing architecture and exposes two entry buttons to the same real Routing LAB. It does not bypass the explicit OUTPUT MUTE / DIRECT/epoch fence. Standalone demo keeps its separate honest preview.
- C++ test extends existing native processor test with same-pointer identity, no duplicate prepare, parameter-processing continuity after publish, protection against stale IDs/revisions, old reader lease and deferred release, and no allocations during RT; Node UI contract verifies SSOT and stable FX design.
