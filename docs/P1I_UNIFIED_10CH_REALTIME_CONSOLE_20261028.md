# P1I — Premium 10-Channel Console → REAL Native Realtime DSP

Baseline: `main@758ec23e959305115d7fc4e23f7c9f73ddad43c8` (P1H, merged native multichannel VST3, GUI v0.8). This extends the existing `PreparedMixerBlock + LiveChannelFxGraph + RealtimeRoutePublisher` without a new audio callback, second engine, or redundant GUI layout. This is a major UI-to-engine correction, **not** full Studio One feature parity.

## Delivered

1. **10 real channel faders/PAN/MUTE/SOLO on the existing premium console** while the native Routing LAB is active and its real device graph has been approved. `web/app.js` passes the native route epoch+revision in control events; `Main.cpp` dispatches all channel IDs 1–10, rejecting old-token updates; `LiveDryRoutingLab` updates atomic per-strip controls of the *same* published graph. Legacy CH1 controls remain unchanged when LAB is stopped. Physical source selection, BUS layout and one stereo-compatible VST3 insert per channel still require the LAB structural APPLY.
2. **No VST3 re-instantiation or device restart for parameter-only edits.** Fader/PAN coefficient calculation occurs in control thread. Audio callback loads atomics once per block; per-channel 64-sample gain ramp suppresses zipper clicks. Independent PRE-send mute/solo gate also ramps, so MUTE suppresses sends without abruptly dropping all buses. Routing DAG, activated hardware port masks, published revision and actual vendor instances stay unchanged. SOLO uses precompiled DAG reachability to keep soloed lane's upstream/downstream path; unrelated channels become silent. No callback heap, JSON, locks, driver I/O or plugin lifecycle operation added.
3. **Truthful premium GUI telemetry.** When the 10CH graph is active, all ten strips display actual native post-fader peak data. CH2–10 no longer pretend to be disconnected, while any empty VST slot is labelled DRY/ROUTE instead of a fake running plugin. FX Rack displays the actual selected per-channel native FX name and opens the same Routing LAB for structural changes. Master FX remain explicitly unavailable; no invented bus or fake editor.
4. **Output safety preserved:** stale epoch/revision event rejected; device topology fault latches silence until explicit remap; structural edits still require OUTPUT MUTE, avoid other thread's independent clock driver, build new graph off RT and preserve CH1 original VST3 + Orbit + preset + GUI. Only param edits bypass structural compile.
5. **Native synthetic acceptance:** `tests/realtime_ten_channel_controls_test.cpp` checks sample-level PRE-fader send at fader=0, SOLO DAG closure, mute-on-PRE, stereo PAN, bus fader, no callback allocation and stale epoch/revision control rejection. Existing JUCE vendor-instance test continues to execute and requires same VST3 identity/lifecycle semantics. One existing Windows workflow reused; no extra CI matrix.

## How to use on real device

- Select and validate a DIRECT ASIO or WASAPI audio device with correct enabled physical input/output masks; configure Routing LAB while **MUTE OUTPUT** is ON and CH1 production FX temporarily removed. For multichannel, enable required inputs in native AUDIO SETUP; JUCE initial 1IN/2OUT requested minimum does not enable every physical input automatically.
- Inside Routing LAB, set CH1–10 physical Mono/Stereo inputs, optional BUS destination, PRE/POST sends, and independent stereo-compatible VST3 effect IDs. Click APPLY while muted. Check native ACK with exact device epoch/revision; unmute carefully at low headphone volume.
- Close LAB panel; use the **normal MIX console** faders, PAN, MUTE, SOLO for all ten strips. Observe actual DSP levels in the strip meters and FX Rack. These parameter movements do not need APPLY and do not recreate VST3. Structural edits remain through Routing LAB and require muting; STOP LAB safely restores previous CH1 host with output held muted.
- Deliberately change hardware device/mask; verify stale UI gestures are rejected, previous channel cannot accidentally route into a newly selected device. Control status re-syncs from native every 12 Hz; preview sessions in browser storage do not supersede native state.

## Limitations / next architecture gates

Still **opt-in LAB**, not full production DAW. BUS uses the same fixed 10 strip slots, not separate AUX pool; only one stereo-compatible VST3/strip in LAB; no full multichannel plug-in editor, portable route state, PDC, hardware CUE/output patchbay or MONO bus layout negotiation. Structural routing APPLY still recreates even unchanged VST3 instances and interrupts tails; that is the NEXT architecture debt. Native strip MUTE/SOLO and PAN have 64-sample interpolation; vendor processors may still allocate/block internally and hardware timing is not validated. The serious #15 0-FX hardware crackle remains open; MSVC+CTest PASS is not hardware proof.

**Next major milestone:** separate 10 physical input strips from aux/subgroup/FX buses and implement stable FX instance ownership through graph changes, one native MixSession/patchbay SSOT. No bulk-merging overlapping stale #115/#117; preserve current approved GUI lightweight/onboard GPU performance. Gate every new iteration with exact-head Windows native + Chromium + physically recorded dry-through FAT.
