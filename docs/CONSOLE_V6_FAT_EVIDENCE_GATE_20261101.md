2026-11-01. Owns integration evidence only. Coordination: #192, ENGINE PR #266, GUI issue #268, hardware blocker #15. Source authority: docs/RELEASE_TRAIN_UNIVERSAL_CONSOLE_V7_20261101.md + docs/workstreams/INTEGRATION_RELEASE_DELIVERY_V7.md (v6 safety retained).

## New validation
The offline CLI scripts/console_v6_fat_gate.mjs has three modes:
- node scripts/console_v6_fat_gate.mjs trace NATIVE_EVENTS.json
- node scripts/console_v6_fat_gate.mjs pcm NATIVE_PCM.json
- node scripts/console_v6_fat_gate.mjs release RELEASE_RECORD.json dist
- node --test tests/console_v6_fat_gate_test.mjs

Trace schema v2: `arsonmix.console-v6.acceptance-trace.v2` validates actual native WebView `arMixConsoleSnapshot`, `arMixConsoleIntent`, `arMixConsoleAck` event envelopes, `schemaVersion:6`, decimal-string uint64 device epoch, accepted graph+roster revisions, ChannelId, native physical pin masks, explicit outputArmed, supportedOps, and telemetry. Intent requires unique session-scoped opaque `requestId`, `baseGraphRevision`, `baseRosterRevision`, `operation`, `targetChannelId`, typed `payload`. ACK must be followed by matching full accepted snapshot; stale/replayed/unsupported intents and invalid duplicated stereo physical pins fail closed. Synthetic self-tests use `provenance.kind=SYNTHETIC`; native exports require explicit source SHA and producer marker, still subject to independent review. **A structurally valid trace does not prove actual JUCE callback or clean physical PCM.** Existing M4 physical OUTPUT can be ARMED with `productionCallbackLive:false`: this is a truthful legacy-output readback, NOT the new universal callback. Never falsify the device output flag to make a v6 fixture pass.

v7 G0 blockers: Native #272 is a control-plane readback without a real JUCE emitter; ENGINE #266 must install the publisher and produce source-owned JSON. GUI #271 still sends resettable `requestId=String(++requestSeq)`; GUI owner must make it unique per WebView session. FAT #270 is NOT G0-complete until source-produced trace and both consumers agree on one SHA. #276 Windows First Sound is staging ONLY, never user UAT.

PCM schema: arsonmix.console-v6.pcm-evidence.v1. Four numeric sample cases: independent_inputs maps distinct IN1->CH7 and IN2->CH2; group_fx_return checks serial GROUP gain, parallel wet-only FX Return, no double-dry and separate GROUP/return mutes; monitor_isolation checks separate physical destinations and MONITOR mute not changing MAIN; physical_mute checks MAIN PCM silence. This checks supplied numerical arrays, NOT their authenticity, plugin vendor identity, VST editor, Show round-trip, real output DAC, or audible cleanliness. The self-tests are synthetic and are not evidence from the actual production callback. ENGINE must export trace/PCM from the genuine production native renderer and include actual device epoch, output pin list, and source SHA; coordinate any wire format changes with both owners in #192. Do not add JS DSP or a second native audio graph.

Release intake requires exact 40-character source SHA, both successful native Windows and Chromium CI rows at exactly that SHA, normal Windows verifier + CTest + Playwright records, actual packaged EXE SHA-256 checked against BUILD_PROVENANCE.json/sourceCommit, and separate ZIP/trace/PCM hashes. The validator does NOT fetch CI run results or ZIP bytes: review Actions links, artifact ZIP hash and WebView2/PE findings independently. Existing scripts/package_native_windows.ps1 and scripts/verify_native_windows_artifact.ps1 remain authoritative for binary packaging. The intake also requires #15 wired 0FX physical run for >=1800 seconds with actual backend/rate/buffer/pins and OUTPUT_ONLY_TONE, CAPTURE_ONLY, DRY_THROUGH reports, full report SHA and human witness. This is an operator evidence record, **not** physical certification; even a complete record returns certified:false and ACOUSTIC_REVIEW_REQUIRED.

## Release stop rules
Do not promote until ENGINE migrates occupied CH1 vendor VST/editor/Orbit, other channels, AUX, MAIN/MONITOR, secondary output and Show to ONE actual callback; real CH11, serial Group, wet FX Return and independent monitor pass native PCM + rollback; GUI reflects ONLY accepted state; one combined exact-head Windows CTest and Chromium+Playwright build and verified Windows GUI artifact pass; physical user+engineer listen to 0FX wired output >=30min without crackle, follow with multiFX/Show/device hotplug and record reports. Do not confuse capture discontinuity or callback timing with render underrun. Never claim 0ms physical latency or sound clean from GitHub CI.


## Field FAT milestone — packaged collector
A verified Windows FAT artifact includes `ArSonMix-Hardware-FAT.ps1` bound to the package manifest by `fatCollectorSha256`; the release verifier also checks its ZIP entry bytes. `Verify`, `Start`, `Stop`, and `Summary` actions record actual operator-timed OUTPUT_ONLY_TONE, CAPTURE_ONLY and >=30-minute wired DRY_THROUGH_0FX into `FAT_RUNS.json`, with diagnostic report SHA-256; `FAT_SUMMARY.json` always sets `hardwareCertified=false`. This is a field record, not acoustic telemetry or an app-controlled audio test. Do not use old ZIPs without this built-in collector; their original FIRST SOUND guide still applies. All device/route/ARM control remains native and manual. The script never tries to load a VST, set a device or authorize output.


## G3 release evidence hardening — real files, one source SHA
The v7 \`release\` action now requires \`artifacts:{zip,nativeTrace,nativePcm,hardwareReport}\` as four safe **basenames** under the extracted local evidence directory, hashes **each real file**, compares their actual SHA-256 to \`artifactSha256\`, \`traceSha256\`, \`pcmSha256\` and \`hardware.fullReportSha256\`, and validates the EXE bytes against \`BUILD_PROVENANCE.json\`. ZIP magic is a fast sanity check only: \`scripts/verify_native_windows_artifact.ps1\` remains the independent full ZIP-entry and embedded BinaryData verifier. All provenance/CIs must refer to **the same exact source SHA**; GitHub workflow status itself still must be independently checked (this CLI does not call GitHub).

The trace file MUST be schema v2 WebView native ACK/PCM state with \`provenance:{kind:"NATIVE_JUCE",sourceSha:"...",producer:"JUCE_WEBVIEW"}\`, and its last accepted native snapshot must advertise **actual** ChannelId production callback, vendor FX/Show/pin-admission, dynamic CH11+, GROUP, FX_RETURN, MONITOR, physically armed output, and live raw/MAIN/MONITOR telemetry. PCM JSON must have the existing four golden PCM cases plus \`provenance:{kind:"NATIVE_JUCE",sourceSha:"...",producer:"JUCE_CALLBACK"}\`. For any missing producer field, **G3 fails closed until ENGINE actually exports it**: never fill the gap with fabricated or manually edited data. An attacker could forge text labels or binary fixture files; therefore native CTest, source-checked real JUCE publisher, Windows package verifier, CI run evidence, and independent human hardware FAT remain separate mandatory checks. The structural unit tests explicitly use fabricated fixture bytes and their expected final result is always \`certified:false\`. This script NEVER authorizes or starts a customer UAT.
