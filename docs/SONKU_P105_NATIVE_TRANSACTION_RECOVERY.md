# SonKu P10.5 native transaction liveness
Follow-up to owner-approved #951; no visual material, geometry, DSP, settings or bridge schema change. Source audit found pending edit prevented periodic snapshot request. A dropped ACK or accepted snapshot could leave the control queue frozen indefinitely. New behavior uses existing 250ms heartbeat and existing read-request throttle, no extra timer and no write retry. Normal transaction still ACK + matching identity-bound snapshot. Missing readback after ACK polls read-only. At 3s, cancel deferred gesture/queued drafts, restore last accepted values and make stage/controls inert while close/power remain available; late applied ID can recover from an identity-bound accepted snapshot without fabricating ACK. Never unlock on stale applied ID or automatically resend a possibly still queued edit. If device cannot answer, timeout is visible and operator can close/reopen. Explicit native rejection continues existing rollback. Regression covers lost readback, missing ACK, stale readback, duplicate ACK, no SET replay and new successful edit. Chromium mock transport is not physical native/ASIO evidence. Parent #951 remains untouched so its expensive qualification stays valid.
