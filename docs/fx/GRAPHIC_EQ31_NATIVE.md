## What is owned where

- `engine/builtin_fx/GraphicEq31Core.h` owns the fixed 31-frequency stereo signal path. 31 matched second-order peaking sections are directly cascaded without adding a callback or allocation. Nominal centres are the ISO/dbx-style 1/3-octave series from 20 Hz to 20 kHz; Q is fixed at 4.318473, so adjacent bands overlap.
- `engine/builtin_fx/GraphicEq31Processor.h` is a native JUCE `AudioProcessor`, controlled by `band0`…`band30` plus the explicitly approved `levelDb` post-EQ Output control. The obsolete **hidden** input/output trims remain removed; legacy saved states migrate safely.
- `src/NativeBuiltInFx.h` registers one catalog descriptor. Existing `FxInstance`, per-ChannelId ordering, per-insert bypass, lifecycle, `.smix` binary storage, device switching and generic owned editor remain the exclusive authorities.
- `web/approved-native-bridge.js` adds a discovery fallback until native `arMixCatalog` returns the canonical descriptor. **No second GUI or WebAudio processing** is introduced.
- `assets/fx/graphic-eq31/slider_eq_grp.svg` is the owner's **byte-exact original 33,354-byte SVG** (`SHA256 aeaf02b8904a667724f34774a692da39a5a466bae302611f347fae4d9fd14dba`). Its three authored children `Track`, `Text`, and `THUMB` are preserved. The production JUCE binary embeds the entire SVG including the original raster/vector THUMB. The editor changes only the `Text` frequency tspan while parsing each band **once** on the UI thread; afterwards it holds the original authored `THUMB` Drawable and applies a simple affine Y transform on parameter changes (no XML reparse, PNG decode, or allocation in the drag path). There are **no JUCE-painted substitute tracks or silver thumbs**; invalid SVG displays a visible error. No BinaryData means the graphical layer cannot render, rather than silently showing a fake substitute.

## GEQ-ENGINE-P0 — realtime coefficient cache and PCM qualification (21 Nov 2026)

**Visual checkpoint is frozen** at `checkpoint/geq31-v13-approved-20261121` (`b850996fbda762b8d9f30af0151a46d918280511`). This engineering change alters **no GUI, SVG, PNG, /preview/ or routing owner**.

### Actual DSP change

- `GraphicEq31Core::prepare(rate)`, in the CONTROL/pre-publication lifecycle, calculates 31 sample-rate-specific `cos(omega)` and `sin(omega)/(2*Q)` pairs plus **361** `10^(dB/40)` gain factors (−24 to +12 dB, every 0.1 dB).
- `setGain()`, called from `consumeRealtimeEdits()` inside the existing audio callback, now uses only constant-bound lookup, optional interpolation and finite arithmetic to calculate its five biquad coefficients. The old per-edit `sin/cos/pow` calls are removed. 0.1 dB APVTS steps land on the lookup; interpolated off-grid values support host automation and legacy state values.
- The existing post-EQ Output Level also uses this prepared factor table squared for `10^(dB/20)`. Neither 31-band updates nor Output Level invoke `pow` on their realtime update path.
- Factory preset recall and the Flat action now use the pre-existing 32-target generation-fenced `setBandsFromPreset()` path: factory presets atomically reset Output to 0 dB, while Flat atomically zeroes 31 bands and preserves current Output. Malformed preset batches are rejected before any parameter write.
- Cache per instance is **361 × 8 + 31 × 2 × 8 = 3,384 bytes**, initialized in `prepare` without heap allocation. No new thread, lock, shared global mutable cache, owner, FIFO, ASRC, render graph or lookahead. During device restart the retained processor's normal host prepare/retirement lifecycle controls the cache. Realtime callback never rebuilds it.
- Existing **5 ms coefficient** and **15 ms output gain** ramps stay in place. Flat-band bypass, no-history at flat, in-place L/R processing, explicit output trim, Nyquist guard and bypass authority are unchanged. Zero added transport frames is distinct from nonzero group delay/phase response of a minimum-phase biquad and physical ASIO latency.

## GEQ-ENGINE-P0 hardening — non-finite upstream PCM and extreme headroom

The core now validates input PCM before processing any filters and sanitizes **only NaN/Inf** to zero. If bad upstream PCM is present, the realtime thread resets **only the affected stereo channel's IIR histories** before processing the sanitized block; the healthy channel retains its audible filter tail. Output values are checked again after active filters to prevent upstream extreme amplitudes or float overflow from poisoning the following block, with the same per-channel recovery isolation. The normal finite path uses no heap allocation, no lock, no extra frame delay, and does not clamp valid samples above 0 dBFS. The added finite validation is a bounded O(frames) scan before/after the existing in-place cascade; evaluate its exact worst-case overhead using the source-profile CTest and physical AUDIO_HEALTH rather than claiming a CPU improvement without results. Recovery from a broken upstream source is intentionally not a normal musical transient.

The existing final JUCE post-EQ Output gain stage also suppresses any **non-finite float caused by explicit Output Level multiplication** before publishing samples back to the mixer. No finite peaks, including amplitudes greater than 1.0, are altered. The accepted-snapshot JUCE test now exercises NaN, Inf, and float overflow with Output Level +6 dB after its smoothing ramp.

The native core tests now inject NaN, Inf, and maximum finite float into active 31-band filters, then verify finite stereo output over subsequent silent callbacks. They also exercise all 31 bands at +12 dB with a 1 kHz sine; filter interaction can produce approximately **+21 dB combined gain**, so valid output PCM may exceed 1.0 (0 dBFS). This is the expected unclamped floating-point response, not an endorsement of physical DAC clipping or a hidden limiter. The operator must lower the explicit Output Level or upstream gain when boosting many adjacent bands.
