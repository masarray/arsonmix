# M1 — explicit deactivation and reusable rack files
Disarm MAIN and STREAM before capture/restore/retiming. Right-click rack header or empty slot: Save FX Rack, Open FX Rack (replace), Insert Saved FX. Right-click occupied native FX: Deactivate & Save FX. Single FX archive is written atomically BEFORE removing its exact slot token. Restore single FX appends with fresh identity; MOVE can place it. A rack file holds ordered catalog IDs, names, verified path/UID, opaque state, individual and rack bypass; no routing, channel gain, device, hotkey, instance IDs, or automatic ARM. File format ARFX0001, bounded 8 slots/8MiB per state/72MiB total, whole-payload SHA256, no executable content imported. Native catalog match required before factory. All preparation and file IO on control, one disarmed graph commit, preserve unrelated leases and existing physical route; rejected candidate leaves prior graph. Recompute PDC, no added delay; other paths may still dominate. Deactivation is archive-and-remove, not persisted inactive placeholder; legacy external CH1 and detached logical-only racks remain unsupported. Open explicitly replaces target rack; user may save old rack first. Native tests include roundtrip and removal of latency; portable test checks catalog replacement and stale rejection. Full Windows and physical acceptance required; no public release.
