## 1. LOCK the behavior (no design decisions remain)
- Ordinary channel on creation → **one real active POST_FADER unity CH→MAIN edge** even with no physical input. Existing saved intentionally disconnected state stays disconnected.
- CH→CH WIRE: one audible enabled edge per ordered pair in MVP, default post-fader. Multiple incoming and outgoing routes allowed, acyclic only. Normal send **retains MAIN**; explicit ROUTE ONLY atomically creates CH→target and removes CH→MAIN; other sends unchanged.
- No separate BUS/FX Return creation workflow now; **any universal channel receiving multiple wires IS a bus** and an insert-reverb channel receiving sends IS an FX return. Preserve current VST3 INSERT rack, existing native AUX/Show sessions and compatibility. Hide the new BUS/FX shortcut buttons in first-release UI, not their runtime legacy data.
- Every accepted CH→MAIN edge remains a **real graph edge**, regardless of display focus. Only the **one uniquely selected channel** may show a short MAIN-color source OUT + pinned MAIN IN fragment pair **while expanded**; both represent ONE edge, not two feeds. In collapsed mode no physical MAIN tail, plug fragment or noisy cable is shown; OUT LED is only for non-MAIN custom sends. Selected CH→CH wires keep source colors; all other cable paths stay hidden. No full-width MAIN line, badges, extra height or changes to approved geometry.
- Focused channel selects exactly its CH→MAIN edge for MAIN jack interaction. MAIN sums N sources, but drag from MAIN jack must never disconnect all. No unique focus: only inspect via the existing Navigator/Matrix. Drag occupied MAIN plug >~10px, release in legitimate empty WIRE bay → disconnect that edge; drop on socket reconnect/replug; Escape/cancel/invalid drop → restore original edge/plug. Click and drag are distinct; a drop on already-connected MAIN cannot accidentally toggle sound off. Everything bound by edgeId.
- WIRE, OUT selector, MAIN, Matrix, Navigator, Scenes/Undo and sockets must derive from **ONE graph**, not unrelated `wireEdges` + `track.output` + `sendSlots` + split-input claims. Physical capture/output patches remain separate from internal routing. During GUI-only work status = SIMULATION; production LIVE only via native accepted graph snapshot + same-revision ACK.
