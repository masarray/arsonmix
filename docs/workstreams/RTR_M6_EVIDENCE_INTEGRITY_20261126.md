# M6: continuous native evidence and lightweight operator presentation

Scope decision: M6 was not in the original RTR M1–M5 plan. This is a measured source defect correction, not a new audio architecture or release lane. Existing histogram includes diagnostic/muted render samples and M4 previously accepted nonconsecutive sequence numbers, mute/rearm and same-epoch transient changes. The 64-pair evidence already knows eligibility boundaries; reuse them with an immutable scope token published only at transitions (not per callback). Control status brackets pressure/histogram reads and rejects a changing scope. JS requires consecutive nominal 1 Hz observations of the same nonzero native token/epoch/revision, armed output and direct single clock; unavailable or mixed observations collect again. Histogram remains approximate, not driver xrun or proof of audible stability. No added audio buffer, clock read, lock, worker, or steady-state atomic write per callback. Existing global histogram remains unchanged for other reports. UI clears stale state at accepted hardware changes and avoids rebuilding identical advice rows. No auto bypass, buffer change, ARM or reroute.
