## Host/lifecycle source audit
LiveChannelFxGraph.h: FxInstance owns processor, preallocates dry and MIDI scratch, seals native control, and retires on control thread after last RT reader. SPSC FxSpsc.h uses bounded lock-free sequence counters. SonKuSpatialProcessor consumes one edit and defers mode-switch ACK until actual fade/mode apply. Existing state byte format untouched. No new locks, allocation or thread introduced.
Common risk: FxInstance::tryCaptureState and render share a nonblocking atomic_flag; if state capture races render, render intentionally clears audio and increments contention. This is a generic FX path, not proof of the reported SonKu crackle. Check capture caller/mute gates and correlate actual contention during field trace. Another source-level liveness risk: if a mode fade is staged while host bypass is fully active, host drains native edits but skips processBlock, so the fade cannot progress until re-enable; distinct from steady orbit overload. Do not conflate or change generic ownership without a separate native lifecycle regression.
LiveAudioEngine.h exposes callbackDurationUs, periodUs, overBudgetCount, callbackGapCount, backendXrunCount (when supported) and cumulative budget histogram. Need same device/epoch differential trace, not reset or hide RT Last warnings. Existing graph and queue mechanisms are not certified by isolated DSP tests.
