# P1K — Ten permanently available INPUT lanes + FOUR dedicated AUX/FX RETURNS
**Base** `main@faee66f475cced8e97bb4e4726b153aa49b10607`: P1J stable vendor processor ownership, P1I realtime 10CH mixer GUI, P4 native ShowV2 wire validation, latest P0 GUI, full native port/epoch fences. The separate GUI optimization PR #133 is intentionally untouched. **This extends the existing live routing DSP**, not a new audio device thread or parallel mixer.

## Meaningful behavior
The previous P1G/H routing compiled exactly 10 total strips: a reverb BUS occupied physical CH10 or another input. P1K adds **four dedicated AUX returns, indexed AUX1..AUX4, outside physical CH1..10**, each stereo with enable, gain, mute, MAIN output control, optional *independent* zero-latency stereo VST3 processor, and a realtime peak meter. All ten source strip inputs may still be assigned while all four AUX returns are active. This is an actual native callback path, not UI-preview.

The existing `PreparedRenderGraph`, `PreparedMixerBlock`, `LiveChannelFxGraph`, `RealtimeRoutePublisher`, `LiveDryRoutingLab` and `NativeDryRouteCommand` remain the **single** engine. No code duplicates or resets Orbit, CH1 production VST host, 10CH real faders, P0 hardware testing, backup or GUIs. Existing internal channel→channel (legacy BUS) sends remain compatible for saved running sessions. New destinations 10–13 identify AUX1–AUX4 distinctly. New compiler validates enabled AUX, gain 0..4, explicit PRE/POST, source CH1..10, bounded send count, no duplicate tap edge, and each bus's valid identity before ACK. AUX cannot send back to INPUT/AUX, so no self-feedback or cycles by construction.

DSP order each block: verified physical input(s) → channel-specific VST3 → PRE SEND (including dedicated AUX destinations) → realtime fader/PAN/mute/solo ramp → channel POST SEND → 4 dedicated AUX buffers → independent AUX stereo VST3 → AUX gain/mute/Master → MASTER. The P1J shared-internal ownership/graph revision remains unchanged: a selected AUX VST3 with same stable AUX slot + native catalog ID + hardware epoch/quantum is reused across route edits, not re-instantiated. Distinct AUX FX lifecycle is prepared off RT and plugin retirements occur only after reader leases. No new locks, callback allocations, or device reopen. AUX scratch is allocated only when an AUX is enabled (up to 8 * 8192 floats in addition to 10 strips), and all send coefficients / sorting / validation are compiled off RT.

In `SIGNAL FLOW → OPEN ROUTING MATRIX`, a new **DEDICATED AUX / FX RETURNS** subsection allows choosing AUX enable, output MAIN, volume, plugin from trusted catalog. Send destination dropdown distinguishes CH 1..10 from AUX 1..4. Native accepted-route SSOT now includes `auxes` and the ACK carries `auxCount`, `auxSendCount`, `auxFxNames` and `auxPeaks`. Route editor reopens from accepted configuration + current live faders, never stale WebView UI state. The premium MAIN mixer strip layout, colors, Orbit button, FX rack and LCD are not touched.

## FAT at real hardware
1. Use approved DIRECT ASIO/WASAPI, verified input mask, no independent clock. Explicitly MUTE OUTPUT and disable legacy CH1 VST chain before starting LAB. Never assume that JUCE opened ten capture ports simply because ten logical inputs exist.
2. `SIGNAL FLOW → OPEN ROUTING MATRIX`. Assign physical IN1…IN10 to CH1–CH10 *only if those ports are actually enabled in AUDIO SETUP*. Enable AUX1 for vocal reverb and AUX2 for another return. The CH1–CH10 assignments remain selectable at the same time.
3. Choose independent zero-latency stereo VST3 reverb on AUX1 and another plugin on AUX2 (or test dry first). Route CH1 PRE→AUX1, CH3 POST→AUX2. APPLY WHILE MUTED. Require native ACK `auxCount=2`, `auxSendCount=2`, `fxCount` matching selected strips/returns.
4. Unmute low-level headphones. Change fader CH1 to -inf: its PRE send remains audible but dry source silences. The POST send from CH3 must follow its fader. AUX volume/mute and MAIN toggle must affect only its independent return, not a source input.
5. MUTE, edit only a send and APPLY: native `fxReused` must include the unchanged AUX VST3. Trigger invalid destination (AUX disabled, unknown VST3, stale epoch, invalid gain or duplicate send): existing native topology remains active, no alternate input fallback.
6. Perform independent #15 zero-FX hardware crackle/clock test; no software CTest can establish zero dropouts at an actual DAC.

## Outstanding architecture gates — not misrepresented
This is **operator-opt-in** 10-input+4-AUX live Routing LAB, not fully integrated DAW-style production FX rack. Each strip and AUX has one stereo-compatible VST3, no multichannel plugin state snapshot restore or PDC, no AUX-to-AUX routing and **no dedicated physical AUX output** yet (all enabled AUX return to stereo MAIN). User still must MUTE while applying structural changes. Existing legacy BUS return within ten strip grid is retained for backward compatibility, but new dedicated AUX should be used instead. A full Studio One/Audition-style production console requires multi-insert rack per strip, AUX/CUE output patching, full Scene recall and hardware #15 qualification. Avoid merging outdated #115/#117 wholesale.
