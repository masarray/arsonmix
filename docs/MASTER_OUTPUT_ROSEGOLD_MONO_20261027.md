# MASTER rose-gold + MONO/STEREO output (2026-10-27)

- MASTER uses the 36×77 static **FADER-ARI-ROSEGOLD.png**, warm silver highlights with more visible rose/copper midtones. It preserves the metallic relief and black center detent, and is embedded once in the final CSS source for offline/WebView2 parity. No PNG filter or blur is applied during drag/hover.
- `#masterMode` is a real BTN-180. Default `STEREO` uses the blue lit state; activating `MONO` changes to red. State is saved as boolean `masterMono` in the existing schema-version-1 session/snapshot JSON; old sessions default to stereo.
- Native `arMixParameter` -> `setMasterMono` -> one relaxed atomic flag in the audio callback. Mono computes `0.5 * (leftPostPan + rightPostPan)` with block-constant coefficients, and supplies the same value to both physical output channels. Stereo uses the original matrix. Mono summing gives 6 dB per-channel attenuation of uncorrelated L/R content, helping avoid hard summation overload; overall headroom still depends on the source signal.
- The `.fader-tools.master-tools` DOM row is removed completely; the MASTER fader zone now expands to the same rail height as channel strips. Latched clip LED buttons are already individually clickable; a click clears that LED and its peak hold. No redundant CLEAR CLIP button.
- UI regression covers 10+MASTER geometry, MODE color/text/aria and session persistence, LED/peak reset; Node contract confirms native parameter and RT mono path. Native Windows and Chromium CI must pass before merge. No additional timer, audio allocation, mutex, or GPU filter.
